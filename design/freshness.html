신선도 배지 — 확정 스펙

가격에는 나이가 있다. 우리가 스캔한 시각(최대 3일 전)과 소스가 그 가격을 마지막으로 관측한 시각(seen, 최대 5일 전)은 다르고, 사용자에게 의미 있는 건 후자다. 딜을 지우는 하드 필터가 아니라 가격에 붙는 신뢰 신호로 쓴다.

01등급 3단계

나이는 방문 시점에 브라우저가 계산한다. 백엔드는 절대 시각만 주고, 배지는 페이지가 캐시돼도 알아서 나이를 먹는다 — 오래될수록 정직해진다.

등급나이표기규칙
fresh < 24h 방금 확인   7시간 전 확인 코랄 점 + --ink 700.
3시간 미만이면 "방금".
ok 24 ~ 72h 어제 확인   2일 전 확인 점 없음. --sub 500.
stale > 72h 4일 전 확인 점 없음 + opacity .7.
확장 상세에만 안내 한 줄 추가.
null seen 없음 스캔 시점 기준 기존 폴백 문구. 화면 안 깨짐.

02어디에 붙나 — 새 요소가 아니라 가격 라벨의 내용

신선도는 딜의 속성이 아니라 가격의 속성이다. 카드에 배지를 하나 더 얹지 않고, 이미 있던 발견가 · 스캔 시점 라벨의 뒷부분을 실제 값으로 치환한다. 새로 먹는 픽셀 0.

03실측 분포 2026-08-20 · 딜 143건

"(허브,도시)당 최저가 1건" 중복 제거가 오래된 캐시를 우대한다(싼 값이 오래 남을수록 이긴다). 호출을 늘려도 이 편향은 사라지지 않는다 — 그래서 지우는 대신 표시한다.

< 3시간 21% < 24시간 (fresh) 36% < 48시간 54% < 72시간 (ok 경계) 74% < 5일 97% < 7일 (하드 컷) 100%

fresh가 1/3 이상 → hero·상단을 채우기 충분. stale은 1/4 남짓 → 흐름을 해치지 않음.
7일 컷은 오늘 기준 손실 0건(실측 최대 5일) — "영원히 안 죽는 유령 가격"만 막는 안전선. 3일로 조이면 딜 26%와 소도시 롱테일이 먼저 잘린다 → 하지 않는다.

04기각한 길

기각
3단계 신호등
신선 보통 오래됨
코랄 단일 시그니처와 색각이상 안전 조합을 동시에 깬다. 무엇보다 딜의 1/4에 빨간 딱지를 붙이는 건 우리 입으로 "이거 못 믿어요"를 외치는 것. 카드 온도가 죽는다.
채택
신선한 것만 조용히 강조
방금 확인 어제 확인 4일 전 확인
등급 차이를 색상이 아니라 명도·굵기·불투명도로만 낸다. 오래된 건 경고하지 않고 사실만 담담하게 적는다. 시그니처 코랄은 "신선"에만 쓴다.
  • 배지를 카드에 새 요소로 추가 → 카드는 이미 사진·도시·가격·날짜·도장·"왜 지금"·태그로 포화. 기존 가격 라벨을 치환하는 것으로 해결.
  • 정렬 토글에 "신선순" 추가 / 필터 도크에 신선도 항목 → 아무도 "신선한 항공권"을 찾아 여행하지 않는다. 신선도는 사용자의 욕구가 아니라 우리의 품질 문제다. 품질 관리를 사용자에게 위임하지 않는다.
  • 핀에 신선도 인코딩 → 핀 색은 이미 가격이다. 두 번째 색 채널은 첫 번째를 못 읽게 만든다.
  • 백엔드가 "3시간 전" 문자열을 구워 내려주기 → 정적 사이트는 하루 한 번 생성. 다음 날 방문자에게 거짓말이 된다.

05신선도가 관여하는 곳 / 관여하지 않는 곳

관여한다
  • hero 게이트 — "진짜 갈래말래?" hero는 fresh 중 할인율 최고. 가장 크게 보여주는 한 장은 가장 믿을 만해야 한다.
    fresh 0건 → ok까지 완화 → 그것도 0이면 전체에서 뽑되 배지는 그대로 노출.
  • 동점 타이브레이커 — 정렬값이 같을 때만 신선한 쪽이 위로.
  • 하드 컷 7일 — 백엔드가 deals.json에서 제외.
관여하지 않는다
  • 정렬 토글은 3종 그대로 — 가성비순·임박순·할인율순.
  • 필터 도크에 신선도 항목 없음.
  • 지도 핀 인코딩 변경 없음 — 색 = 가격.
  • 딜 개수 변화 없음(7일 컷은 현재 0건 제외).

06계약 영향 — deals.json

필드 추가라 안전(프론트가 무시해도 깨지지 않음). 전체 스펙은 CONTRACT.md.

필드타입예시의미
seenstring | null "2026-08-18T03:17:35+09:00" 소스가 이 가격을 마지막으로 관측한 시각. ISO8601, KST.
⚠️ 타임존을 반드시 정규화할 것. API 원본 found_at은 오프셋 없는 naive 문자열이고 UTC로 보인다 (KST로 간주해 계산하면 최대 나이가 80h — 3일 수집 창 + 9시간과 정확히 맞아떨어진다). 그대로 흘리면 모든 딜이 9시간씩 늙어 보인다. 오프셋을 붙일 수 없으면 null을 보낸다.
